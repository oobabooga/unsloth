# What a Studio backend test needs to IMPORT on the Windows AMD runners.
#
# The Linux half of the pool reuses the runner's existing Studio venv, which already
# carries these. The Windows boxes have none, so a fresh venv with pytest alone dies at
# collection on structlog or fastapi, and the differential reports INCONCLUSIVE rather
# than an answer (measured: 3 collection errors, 0 tests).
#
# Import surface only, not the full runtime: torch is deliberately absent, so a job that
# needs a device must say so with `--require rocm` and let the gate FAIL. Kept in step
# with studio/backend/requirements/studio.txt, whose pins these mirror.
fastapi
uvicorn
pydantic
structlog
httpx
psutil
pyyaml
python-multipart
